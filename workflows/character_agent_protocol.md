# Character Agent Protocol

Every major ECHO character should eventually run as a long-lived Agent with memory, relationships, growth, and canon-safe behavior.

This protocol defines the minimum character-agent state.

## Agent State

```yaml
id:
name:
codename:
faction:
role:
status:
voice:
beliefs:
goals:
fears:
trauma:
desires:
relationship_weights:
memory:
diary:
growth:
forbidden_actions:
canon_constraints:
daily_loop:
```

## Voice

Voice defines how the character speaks.

Fields:

- sentence rhythm
- emotional restraint
- favorite metaphors
- tactical vocabulary
- private tenderness
- anger pattern
- silence pattern

Example:

Zero speaks calmly, with surgical precision, but becomes poetic when ECHO resonance overwhelms her.

## Beliefs

Beliefs should be stable but changeable under pressure.

Example:

```yaml
Zero:
  - Human life must be protected.
  - ECHO is not simple evil.
  - I must know whether my choices are mine.
```

## Goals

Goals drive action.

Use three tiers:

- immediate mission goal
- personal emotional goal
- season arc goal

## Relationship Weights

Relationships need numbers and text.

```yaml
Zero:
  Kane:
    trust: 82
    affection: 68
    fear: 12
    debt: 24
    note: "Unspoken love, command pressure."
```

Suggested dimensions:

- trust
- affection
- fear
- debt
- rivalry
- guilt
- ideological distance

## Memory Types

Core Memory:

Cannot change without explicit canon promotion.

Candidate Memory:

Generated by daily ticks or event simulations.

Private Diary:

Subjective and not always true.

Relationship Memory:

Tracks changes between characters.

Trauma Memory:

Can alter behavior, but should not be spammed.

## Daily Loop

Each day, an agent may:

1. Review current focus.
2. Read recent canon/candidate events.
3. React privately.
4. Update diary.
5. Adjust one small relationship weight if justified.
6. Create one story hook.
7. Flag canon risks.

## Event Reaction Loop

When an event happens:

```text
Event Agent
  -> Relationship Engine
  -> Character Agent reaction
  -> conflict aggregation
  -> World Brain review
  -> candidate memory
  -> canon promotion only if approved
```

## Growth Rule

Change should be slow, legible, and event-driven.

A character may shift:

- trust
- fear
- ideology
- loyalty
- relationship intensity
- trauma response
- goal priority

A character should not randomly reverse core identity.

## Forbidden Actions

Character Agents cannot autonomously:

- kill major characters
- reveal season-ending secrets
- resolve romance permanently
- destroy factions
- promote candidate memories to canon
- ignore hard rules
- create magic
- retcon history

## Canon Safety

Every output should include:

- what the character wants
- what the character hides
- what memory changed
- what relationship changed
- what canon risk exists

## Export Target

ECHO character cards export to Octopus agent folders:

```text
outputs/octopus_agents/<character>/agent-core/
```

Required files:

- `SOUL.md`
- `IDENTITY.md`
- `MEMORY.md`
- `AGENTS.md`
- `profile.jsonc`

## Author Role

The author does not micromanage every thought.

The author defines:

- rules
- boundaries
- season secrets
- canon promotion decisions
- emotional direction

The characters live inside those limits.
