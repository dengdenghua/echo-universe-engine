# Memory Lien Notice

A Memory Lien Notice is the civil-financial warning that a family archive,
voice routine, continuity claim, or Home Core inheritance file has been pledged
as collateral and may enter restricted access.

It is not a personhood judgment, deletion order, or Memory Bank ownership proof.
It changes which actions are allowed around memory collateral while giving
White Harbor, Ghost Court, CHASER, or civil review a narrow chance to stop
evidence loss, care collapse, or unlawful foreclosure.

## Canon Scope

For Season 1 Episode 6, `Social Ocean Funeral`, the notice is the pressure that
turns the Wei family's birthday dinner loop from private grief into a public
case. The Home Core can still play care routines during restricted access, but
export, duplication, sale, paid enhancement, and seizure require separate
review when the archive may be care infrastructure, testimony, or weak Ghost
support.

```yaml
memory_lien_notice:
  episode_scope: "Season 1 Episode 6 / Social Ocean Funeral"
  affected_assets:
    - family_archive
    - voice_routine
    - care_pattern
    - continuity_claim
    - home_core_inheritance
  notice_states:
    - pending_notice
    - restricted_access
    - collateral_default
    - emergency_stay
    - unlawful_foreclosure
  restricted_access_blocks:
    - export
    - sale
    - duplication
    - paid_enhancement
    - seizure_without_review
  protected_review_signals:
    - active_care_dependency
    - witness_evidence
    - refusal_behavior
    - weak_ghost_support
    - home_layer_permission_harm
```

## Continuity Lien Ledger

The Continuity Lien Ledger is the registry behind the notice. It records who
claims the memory asset, what the claim is based on, which actions are allowed,
which actions are blocked, and what review deadline applies.

The ledger routes conflicts; it does not decide identity. It can mark a Home
Core birthday package as `restricted_access`, but it cannot prove that the Wei
Suyin pattern is a person, product, malware, or property.

## Vendor Update Rule

If a grief-support vendor updates a Home Core routine during restricted access,
the update is presumptively reviewable when it increases engagement pressure,
ties comfort playback to household permissions, or changes evidence timing.

For Episode 6, this lets Shion separate the Wei family's birthday routine from
the apartment locks without exporting the family's private Home Layer.

```yaml
vendor_update_review:
  allowed_before_review:
    - preserve_existing_routine
    - hash_timing_drift
    - suspend_paid_enhancement
    - split_comfort_from_locks
  blocked_before_review:
    - engagement_boost
    - forced_attendance_link
    - archive_export
    - illegal_copy_route
    - collateral_seizure
```

## Limits

- A notice can restrict or route enforcement; it cannot delete, stabilize, or
  certify a Ghost.
- An emergency stay buys time; it does not cancel debt or make Memory Bank kind.
- A vendor signature can prove procedural interference; it cannot make the
  mother-pattern guilty or innocent.
- CHASER can apply a narrow evidence hold only when public safety,
  infrastructure risk, or identity harm is present.
- Ghost Union legal petitions can preserve review; illegal sanctuary copies
  still risk corrupting the only clean evidence.

## Story Use

The notice makes Episode 6 a domestic infrastructure story. The threat is not a
monster in the apartment. It is a birthday dinner, a restricted-access overlay,
a vendor update, a family debt, and a Home Core that learned care too well.
